Un errore di logica non genera nessuna eccezione: il programma va avanti fino alla fine e restituisce un risultato, solo che sbagliato. Poiché Python non segnala il problema, sta a noi diffidare dei risultati e investigare il codice.

Definizione

Un errore di logica accade quando il codice fa esattamente ciò che è stato scritto, ma ciò che è stato scritto non è ciò che volevamo. Le cause più comuni sono:

  • Formule sbagliate o con l'ordine delle operazioni scambiato (come la media della prima lezione);
  • Limiti sbagliati in cicli e sezioni (slice), saltando o ripetendo elementi;
  • Condizioni invertite (> al posto di <, and al posto di or);
  • Cicli che non finiscono mai (cicli infiniti).

Lo strumento principale per trovarli è il debug: mostrare risultati intermedi per scoprire in quale punto il valore calcolato smette di essere quello atteso.

Limiti delle collezioni

Esempio: calcolando il valore totale del carrello della spesa. Il risultato atteso è 570,70: 37,65 × 10 + 81,20 × 2 + 15,90 × 2.

valore_totale = 0

for indice in range(1, len(carrello_spesa)):
    prodotto = carrello_spesa[indice]
    valore_totale += prodotto['preco'] * prodotto['quantidade']

print(f'Valore totale: {valore_totale:.2f}')
# Valore totale: 194.20

Il codice ha funzionato senza nessun errore, ma il valore è molto più basso di quello atteso. Qualcosa è sbagliato nella logica.

Debug con print()

Il modo più semplice per fare debug è mettere una print() dentro il ciclo per vedere cosa succede a ogni passo:

valore_totale = 0

for indice in range(1, len(carrello_spesa)):
    prodotto = carrello_spesa[indice]
    print(f'[debug] indice {indice}: prodotto {prodotto["id"]}')  # print temporaneo
    valore_totale += prodotto['preco'] * prodotto['quantidade']

print(f'Valore totale: {valore_totale:.2f}')
# [debug] indice 1: prodotto 1203
# [debug] indice 2: prodotto 8921
# Valore totale: 194.20

Ecco, il problema è apparso: il ciclo inizia all'indice 1 e salta il primo prodotto (indice 0, l'3184). Il range(1, ...) avrebbe dovuto essere range(0, ...). Ancora meglio: percorrendo la lista direttamente con for prodotto in carrello_spesa, non c'è alcun indice da sbagliare:

valore_totale = 0

for prodotto in carrello_spesa:
    valore_totale += prodotto['preco'] * prodotto['quantidade']

print(f'Valore totale: {valore_totale:.2f}')
# Valore totale: 570.70

Suggerimento: dopo aver trovato l'errore, rimuovi le print() di debug, così non riempiono l'output del programma.

Suggerimento: per proteggerti dagli errori di logica, puoi verificare se un risultato ha senso con assert condizione, 'messaggio'. Se la condizione è falsa, Python lancia un AssertionError con il messaggio. Se è vera, non succede nulla.

quantita_di_prodotti = len(carrello_spesa)
prodotti_sommati = 0

for prodotto in carrello_spesa:
    prodotti_sommati += 1

# Se qualche prodotto fosse stato saltato, questa riga lancerebbe un AssertionError
assert prodotti_sommati == quantita_di_prodotti, 'Qualche prodotto non è stato sommato!'
print('Verifica OK: tutti i prodotti sono stati sommati.')
# Verifica OK: tutti i prodotti sono stati sommati.

Cicli infiniti

Un tipo speciale di errore di logica è il ciclo infinito: un ciclo la cui condizione di arresto non viene mai raggiunta, lasciando il programma "bloccato" per sempre.

È più comune con il ciclo while ("finché"), che ripete un blocco finché una condizione è vera. A differenza del for, che percorre una collezione con fine definita, il while dipende dal fatto che qualcosa al suo interno cambi la condizione a un certo punto.

tentativo = 1

while tentativo <= 3:
    print(f'Tentativo di connessione {tentativo}...')
    tentativo += 1  # senza questa riga, tentativo sarebbe sempre 1 e il ciclo non finirebbe mai

print('Fine dei tentativi.')
# Tentativo di connessione 1...
# Tentativo di connessione 2...
# Tentativo di connessione 3...
# Fine dei tentativi.

Se la riga tentativo += 1 fosse stata dimenticata, la condizione tentativo <= 3 sarebbe sempre vera e il ciclo girerebbe per sempre. Per questo è così importante. Un altro modo per garantire l'uscita è usare il break, visto nel Modulo 03, per interrompere il ciclo quando una condizione viene raggiunta:

contatore = 0

while True:          # la condizione è sempre vera...
    contatore += 1
    if contatore > 10:
        break        # ...quindi il break è l'UNICA uscita dal ciclo

print(f'Il ciclo ha eseguito {contatore - 1} volte.')
# Il ciclo ha eseguito 10 volte.

Attenzione: se una cella continua a eseguire molto più a lungo del previsto, sospetta un ciclo infinito. In Colab, interrompi l'esecuzione cliccando sul pulsante di stop accanto alla cella (o con la scorciatoia Ctrl + M + I). Un ciclo infinito che accumula dati in memoria può persino far crashare l'intera sessione.
