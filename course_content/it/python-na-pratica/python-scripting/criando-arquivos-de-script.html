Un file di script è un file di testo con estensione .py contenente diverse righe di codice Python, salvate insieme per essere eseguite (e rieseguite) in una sola volta, sempre nello stesso modo. È il formato usato per le automazioni reali — qualcosa che deve funzionare da solo, senza un notebook aperto.

Su Google Colab

Colab non ha un editor di file tradizionale, ma puoi creare un file .py direttamente da una cella con il comando magico %%writefile nome_do_arquivo.py: tutto ciò che viene dopo questa riga, nella stessa cella, viene salvato nel file.

Esempio: uno script che riceve un nome dalla riga di comando e stampa un saluto.

%%writefile saudacao.py
import sys

nome = sys.argv[1]
print(f'Olá, {nome}!')
# Writing saudacao.py

Il modulo nativo sys conserva, nella lista sys.argv, gli argomenti della riga di comando: sys.argv[0] è sempre il nome dello script stesso, e sys.argv[1], sys.argv[2]... sono i valori extra forniti da chi ha eseguito il comando.

Ora eseguiamo il file appena creato, passando 'Maria' come argomento:

!python saudacao.py Maria
# Olá, Maria!

Attenzione: se lo script viene eseguito senza l'argomento previsto (!python saudacao.py, senza nessun nome), sys.argv avrà solo un elemento (sys.argv[0]), e tentare di accedere a sys.argv[1] genera un IndexError. Gli script per uso reale di solito verificano se gli argomenti necessari sono stati forniti prima di usarli.

Esempio (mondo reale): uno script di automazione che consulta un tasso di interesse su un sito e registra il risultato, con data e ora, in un file .csv — il tipo di compito che normalmente funziona da solo, a un orario programmato (es: tutti i giorni alle 9).

Questo è il contenuto di un file extrair_taxa.py, mostrato qui solo per lettura — non viene eseguito da questo notebook, poiché dipende dall'accesso a internet e da un servizio esterno che può cambiare col tempo. È esattamente questo tipo di compito, però, che ha senso eseguire come script, e non dentro un notebook.

import os
import json
from datetime import datetime

import requests

URL = 'https://exemplo-api-financeira.com/taxa-cdi'
ARQUIVO_SAIDA = 'taxa-cdi.csv'

data_e_hora = datetime.now()
data = data_e_hora.strftime('%Y-%m-%d')
hora = data_e_hora.strftime('%H:%M:%S')

# Consultando a taxa no site
try:
    resposta = requests.get(URL)
    resposta.raise_for_status()
except requests.HTTPError:
    print('Taxa não encontrada, mas o script vai continuar.')
    taxa_cdi = None
except Exception as erro:
    print('Erro de conexão, interrompendo o script.')
    raise erro
else:
    dado = json.loads(resposta.text)
    taxa_cdi = float(dado['taxa'].replace(',', '.'))

# Criando o arquivo com cabeçalho, caso ainda não exista
if not os.path.exists(ARQUIVO_SAIDA):
    with open(file=ARQUIVO_SAIDA, mode='w', encoding='utf8') as arquivo:
        arquivo.write('data,hora,taxa\n')

# Só registra a linha se a taxa foi obtida com sucesso
if taxa_cdi is not None:
    with open(file=ARQUIVO_SAIDA, mode='a', encoding='utf8') as arquivo:
        arquivo.write(f'{data},{hora},{taxa_cdi}\n')
    print('Sucesso!')

Suggerimento: le API dei siti cambiano col tempo (indirizzo, formato della risposta ecc.). Prima di usare un'API esterna in un progetto reale, controlla sempre la documentazione ufficiale e aggiornata del servizio.

Sulla tua macchina locale

La dinamica è la stessa, cambia solo lo strumento usato per creare il file:

  1. Crea il file .py con un editor di testo o di codice;
  2. Salva il file nella cartella dove hai aperto il terminale;
  3. Esegui con lo stesso comando usato in Colab, senza il ! (che esiste solo dentro il notebook).
python saudacao.py Maria

Strumenti di sviluppo (IDE)

Un semplice blocco note funziona per scrivere .py, ma una IDE (Integrated Development Environment, Ambiente di Sviluppo Integrato) rende il lavoro molto più produttivo: evidenzia errori di sintassi prima che tu esegua il codice, suggerisce l'autocompletamento, permette di fare debug del codice passo dopo passo e viene già con un terminale integrato.

Le due opzioni più usate nel mercato sono:

  • Visual Studio Code, di Microsoft, gratuito e leggero — la raccomandazione più comune per iniziare;
  • PyCharm, di JetBrains, più robusto e focalizzato specificamente su Python, con una versione gratuita (Community) e una a pagamento (Professional).

Suggerimento: lo stesso Visual Studio Code ha un'estensione ufficiale di Jupyter/Colab, che permette di aprire ed eseguire notebook .ipynb (come quelli di questo corso) senza uscire dall'editor.
